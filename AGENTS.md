# Project knowledge

- This is an hg19 UCSC `chr`-named WXS/WGS germline workflow. Keep the public name `WxsGermlineHg19` for compatibility. A supplied `capture_bed` selects WXS scope; an omitted `capture_bed` selects WGS full primary-contig scope. Never infer mode from `target_bed`.
- `capture_bed` is optional and defines WXS assay/calling scope when supplied. `target_bed` is optional and may only affect downstream target derivation. Never use report targets to narrow alignment, BQSR, or the primary HaplotypeCaller gVCF.
- BED inputs are 0-based half-open. WGS uses full `chr1`–`chr22`, hg19 UCSC `chrM`, and X/Y partitions when the complement is specified; WXS uses their intersections with `capture_bed`. Unsupported or excluded contigs are recorded, not silently reported as reference.
- The native GATK gVCF is an intermediate test artifact. Target-region all-sites VCF is also an intermediate. Do not assert report readiness or fill missing genotypes as `0/0` without validated per-target evidence.
- The local `doc/` directory is intentionally ignored by Git. Keep public implementation status in README/CHANGELOG/TODO because the research document may not be shared.
- The root `.gitignore` is an allowlist. Keep deployable Choppy `defaults`/`inputs`/`schema.json`/`manifest.json`, `inputs.example.json`, and public `docs/` visible to Git; keep local `doc/` ignored.
- The deployable hg19 reference and known-sites defaults use `oss://reference-data/hg19_ucsc/`. The previous `oss://genomics-platform-reference-data/` bucket is stale. A bucket name correction does not verify the object keys or backend mount access.
- Keep the root `workflow.wdl` as the orchestration entry point and put each task in its own `tasks/*.wdl` import. Maintain deployable workflow and dependency documentation in tracked `docs/`; keep `doc/` for local research only.
- Sequencing input is exactly one already merged R1 FASTQ and one already merged R2 FASTQ per sample (`File`, not arrays). Do not add lane scatter, lane IDs, or BAM merging unless the user changes this input contract.
- `PrepareCapture.analysis_bed` is the union of actual autosomal, enabled X/Y, and chrM calling partitions. `bqsr_bed` excludes chrM and trains on autosomal plus enabled X/Y partitions; the recalibration table is applied to the full BAM. Keep `calling_bed` as the autosomal HaplotypeCaller interval and preserve separate ploidy-specific sex gVCFs. In XY, exclude only the exact chrY PAR overlap from the scope exclusion report.
- The hg19 UCSC `chrM` reference is 16,571 bp and differs from rCRS/GRCh37 chrMT numbering. Call chrM within the selected WXS/WGS scope in a separate Mutect2 mitochondrial-mode branch; its VCF is an intermediate, with no hom-reference inference or clinical heteroplasmy claim. Verify circular breakpoint, NuMTs, allele fractions, and assay coverage before reporting.
- Image provenance: the five original `choppy-pipe` tool tags occur in CyanZRoy/wxs_somatic_gatk_ref at commit `8894a1f9fafaf6f43c00fe91e0089fc6abd21e41`. Project-supplied `doc/bu_info.txt` moves all five tool tags and the local Python `3.11-slim` tag to `crpi-xvcezojsbq275htp.cn-shanghai.personal.cr.aliyuncs.com/nap_hub/`; this is an address change, not proof of identical image contents or registry access. `analysis_image` must provide BWA, samtools, and GATK; `gatk_image` also needs samtools for ApplyBQSR output indexing. Record platform, digest, actual tool paths and versions before deployment.
- Cluster defaults use the six `cpu*mem*_cluster_config` names and ECS values from CyanZRoy/wxs_somatic_gatk_hg38_instant `defaults`. Keep `defaults`, the Choppy `inputs` template, and `workflow.wdl` aligned when changing image or cluster defaults. Fastp defaults to 8 threads on the 8-vCPU class; alignment and Qualimap use the workflow `threads` input (default 16).
- Within a WDL task, input and output declarations share one name scope. Keep input names distinct from output names (for example `input_bam` versus output `bam`) and update `workflow.wdl` call keys when changing a task input.
- Choppy task call directories can have slow mounted I/O. For every new or changed analysis task, save `call_dir`, copy computation inputs and their required sidecar indexes into a unique `/tmp` work directory, run tools and temporary files there, then copy declared outputs back to `call_dir`; never use symlinks to mounted inputs for computation. Resolve relative localized input paths against `call_dir` after changing directory. Lightweight input-presence checks need not copy whole FASTQ/BAM files. Check that `/tmp` is node-local and size `systemDisk` for staged inputs, intermediates, and output copies on the target backend.
- Choppy's extensionless `script`, `stdout`, and `stderr` are inconvenient to open in its UI. Register an EXIT trap early in each task to copy any existing ones to `script.txt`, `stdout.txt`, and `stderr.txt` in `call_dir`, including on task failure. Keep the original logs and do not let diagnostic-copy failure mask the task exit status.
- After every WDL edit, run `python3 -m unittest discover -s tests` from the Ubuntu-24.04 WSL repository directory, then validate the root workflow with all imports using `& .\scripts\validate_wdl_wsl.ps1` from Windows Codex. The script uses WSL Java and `/opt/cromwell/81/womtool-81.jar`; `/opt/cromwell/81/cromwell-81.jar` is the matching engine. From WSL in this repository, the equivalent command is `java -jar /opt/cromwell/81/womtool-81.jar validate workflow.wdl`. Codex's sandbox may deny `wsl.exe`, in which case the tool call needs the appropriate approved escalation. Treat a nonzero validation result as a WDL issue to fix before delivery. This validation does not execute tasks or validate Choppy backend settings.
